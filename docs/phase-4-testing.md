## Automated and isolated-browser verification

The unit/regression suite covers legacy records, block validation/actual recurrence, overlapping courses, safe JSON round-trips, calendar exclusion/default inclusion, appearance normalization/persistence/system changes, safe diagnostics, manifests, newest grade-source URLs and stale editor protection. The full suite and Chrome/Firefox packaging are run before the PR is opened.

An isolated Chromium fixture checks the real packaged main panel and popup, dark/light/system changes, compact row geometry, plan-specific block creation/editing/conflict labels, latest OVERALL navigation, courses-only versus opted-in ICS, Google preview inclusion (canceled before any write), portable JSON and redacted diagnostic files. Network/API/account data are fixtures. No real Workday registration or Google Calendar writes occur.

## Remaining real-browser release checks

Use a real UBC account for Workday navigation, live lookup availability, consent prompts, native downloads and refreshed browser permissions. Repeat in Firefox with its ICS-only package. Check system appearance changes, a narrow popup, long text, keyboard focus and actual browser zoom. Check Google sign-in, sign-out and revocation on a test account only when intentionally doing that manual release validation. These fixture checks do not claim a full screen-reader/accessibility audit, store publication or live account acceptance.
