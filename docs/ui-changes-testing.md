# Manual tests for the latest schedule and sync UI

Reload the updated extension and refresh Workday. These checks cover visible changes; fixture tests do not establish real-browser layout or live Google behavior.

| Test | What to look for |
| --- | --- |
| Widget logo | The existing extension logo appears immediately to the left of the widget title. It should load in Chrome and Firefox, stay aligned with the title and leave the header controls usable. |
| Quiet navigation | Navigate to another Workday page with the widget open. The page-change message no longer appears; your working courses remain available and Refresh still imports the current page. |
| Save tooltips | Hover or Tab-focus each enabled save icon: its tooltip appears below the button and slides downward into view, stays inside the widget, and is not hidden by the header or course-list controls. |
| Calendar header alignment | In Schedule view, the status chip sits at the left on the same row as the centered schedule name/term pill. It must not create a separate row above the heading, overlap long names, or move the Week 1 / Week 2 controls outside schedule-controls. |
| Schedule heading, panel and popup | Your saved schedule name is first, with its term below, e.g. **Fall Plan** then **Winter Term 1**. Rename/load another saved schedule and check the heading updates. Multiple-term plans show **Multiple terms detected** in both views; an unnamed plan says **Working Schedule**. |
| Save controls | The old toolbar Save Schedule button is gone. Beside the centered course heading are two theme-matched icon buttons: **Quick Save** (`save`) and **Save As New** (`save_as`). Hover or Tab-focus shows the correct labels. No text appears inside the buttons. |
| New schedule | Import courses: heading is **Working Schedule**, both chips are orange **Working - not saved**, and Quick Save is disabled. Save As New opens a name prompt; Cancel keeps courses, heading, chips and saved records unchanged. Confirm creates a saved schedule and turns both chips green **Saved Schedule**. |
| Editing and Quick Save | Load a saved schedule, then add/remove a course or change a course color. Its name stays in both headings; both chips become orange and Quick Save stays enabled. Quick Save asks before overwriting: Cancel leaves edits and the saved copy unchanged; Update replaces that same saved record, keeps its name, creates no duplicate, and turns both chips green. Reload that saved schedule to verify the edits persisted. |
| Separate saved copy | Edit a saved schedule and use Save As New. Confirm a new name, then check both records in My Schedules: the original keeps its old courses; the new record has your edits and becomes the current green saved schedule. Reusing an existing name must be rejected without changing either schedule. |
| Unique schedule names | Save **Fall Plan**, then try Save As New with **Fall Plan**, **fall plan**, or ** Fall   Plan **. Each is rejected with an inline error, the dialog stays open, and the saved record and working edits stay unchanged. Enter a distinct name to save successfully. Try renaming another schedule to an existing name in both the Workday panel and popup: it must be rejected. Keeping the same schedule’s own name or changing only its capitalization is allowed. Quick Save must still update its existing record. |
| Status consistency | Switch between Course List and Schedule: both chips must match. Search, sorting, Week 1 / Week 2 and time format changes must not mark a saved schedule as edited. Load or rename a saved schedule and verify both headings update. |
| Empty or deleted source | Clear produces gray **No courses added yet**, heading **Working Schedule**, and disabled save controls. Removing all courses individually also produces gray; the loaded saved name and Quick Save association remain until you clear/load/delete. Delete the current saved record (also try in another Workday tab or the popup): working courses remain, heading becomes **Working Schedule**, chips turn orange (gray if empty), and Quick Save becomes disabled. |
| Save failure, if encountered | A failed write shows an error, preserves the previous saved record and keeps edits orange with Quick Save still available. The green state must appear only after a successful write. This is also covered by simulated delayed/failed writes in automated tests; no need to force a browser-storage failure manually. |
| Course-view heading | Above the course-list controls, expect a centered plain schedule name with the term below. It must match the schedule-view heading, update after saving/loading/renaming, and have no pill background or rounded border. |
| Week controls | Week 1 / Week 2 sit inside the schedule controls, beneath the heading, outside the scrolling timetable. Repeated toggles must not duplicate controls. Buttons use the extension’s purple theme, two-pixel borders, ten-pixel corner radius, and clear hover/focus states. The selected week has a filled purple background with light text. Weekly classes remain in both; anchored alternating sections switch weeks. Check both the main panel and popup. |
| Grade buttons | Supported course-list and Workday registration buttons read **Average: 80.0%** (with the actual latest value), or **Average: N/A** when unavailable. The five-year number stays outside the grade button. Clicking a resolved grade still opens UBCGrades. |
| Info control styling | The control to the right uses the Google Material Symbols **info** icon, the same 34 Ã— 34 pixel size and ten-pixel corner radius as the adjacent delete button, theme colors, a two-pixel border and a background matching the grade button. The info icon color matches its border, including when course colors change; check the course list and registration page. Its cursor stays the normal arrow when hovered. Hover/Tab-focus still shows the five-year average, or N/A, without a details paragraph. |
| Sync confirmation labels | Expect **Target Calendar: Primary**, **Schedule Name:**, and **Adding**, **Updating**, **Removing**, **Unchanged** each on its own line. There is no Dates row or older-unscoped-imports warning. |
| Skipped list | A schedule with missing/invalid meeting data lists **Skipped:** followed by the actual course/section and reason for each skipped meeting. A schedule with no skips says **Skipped: None**. Long lists should scroll within the dialog. |
| Confirmation spacing and safety | A blank line separates the holiday sentence from the preceding summary/warnings. Cancel still makes no calendar changes. Old events without schedule IDs remain preserved even though their warning is hidden. |

Term labels prefer explicit term metadata; otherwise they summarize the meeting-date seasons for display only. Week selection does not change the full saved/exported schedule. Holiday exclusions still require verified exception dates supplied in Workday data.
